# Конфигурация виртуальной машины devops-vm

## 1. Параметры машины
- Объём памяти: 2048 МБ
- Количество ядер: 2
- Объём диска: 25 ГБ

## 2. Сетевые интерфейсы
- Адаптер 1: NAT (10.0.2.15) — доступ в интернет.
- Адаптер 2: Host-only (192.168.56.101) — доступ с хостовой системы.

## 3. Правило проброса портов
- Порт хоста: 2222 -> Порт гостя: 2222 (SSH)

## 4. Учётные записи
- `student` — базовая учётная запись.
- `devops` — рабочая учётная запись, группа `sudo`, вход по ключу.

## 5. Служба SSH
- Порт: 2222
- Файл конфигурации: `/etc/ssh/sshd_config.d/99-hardening.conf`
- Директивы: `PermitRootLogin no`, `PasswordAuthentication no`, `MaxAuthTries 3`, `AllowUsers devops`.

## 6. Правила межсетевого экрана
- Политики: `deny incoming`, `allow outgoing`.
- Разрешено: 2222/tcp (LIMIT), 80/tcp, 443/tcp.

## 7. Снимки состояния
- `01-clean-install`
- `02-keys-configured`
- `03-ssh-hardened`
- `03-ufw-configured`

## 8. Веб-сервер
- Устанавливаемый пакет: `nginx`
- Путь к конфигурации ресурса: `/etc/nginx/sites-available/devops-site`
- Каталог ресурса: `/var/www/devops-site` (владелец `devops:devops`, права 755)
- Пути к сертификату и ключу: `/etc/ssl/certs/devops.crt` (644), `/etc/ssl/private/devops.key` (600 root)
- Команда формирования сертификата: `sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout /etc/ssl/private/devops.key -out /etc/ssl/certs/devops.crt -subj "/CN=devops.local" -addext "subjectAltName=DNS:devops.local"`
- Срок действия: 365 дней.

## 9. Контейнеризация
- Способ установки Docker Engine: официальный репозиторий Docker (не docker.io).
- Участники группы `docker`: `devops`.
- Расположение проекта на сервере: `/home/devops/app`.
- Расположение файла `.env` и его права: `/home/devops/app/.env` (права 600).
- Публикуемые порты и адреса: `127.0.0.1:5000` (только локально).
- Именованные тома: `app_db_data`.
- Конфигурация обратного прокси-сервера: Nginx проксирует запросы с `https://devops.local/app/` на `http://127.0.0.1:5000/`.


## 10. Ansible

Проект Ansible находится в каталоге `ansible/` репозитория `devops-course-2026`. Управление выполняется из WSL Ubuntu 24.04.4 LTS. Используется Ansible Core 2.16.3.

### Управляющий и управляемый узлы

- Управляющий узел (Control Node) — WSL Ubuntu.
- Управляемый узел (Managed Node) — виртуальная машина VirtualBox `devops-vm` с Ubuntu Server 24.04 LTS.
- Подключение к виртуальной машине выполняется по SSH на порт 22.

### Inventory

В проекте используются два inventory-файла:

- `inventory/bootstrap.ini` — первоначальное подключение к VM под пользователем `student` с парольной аутентификацией.
- `inventory/prod.ini` — дальнейшее управление под пользователем `devops` с помощью SSH-ключа `~/.ssh/devops_vm`.

После первоначальной настройки парольная SSH-аутентификация отключена. Для последующих запусков используется `prod.ini`.

### Учётные записи

- `student` — временная учётная запись для первоначальной настройки сервера.
- `devops` — учётная запись для постоянного автоматизированного управления. Она имеет права sudo без запроса пароля и использует SSH-ключ.

Пароли и закрытый SSH-ключ в репозитории и документации не хранятся.

### Роли Ansible

Конфигурация разделена на четыре роли:

- `base` — установка базовых пакетов, настройка репозитория Docker и установка Docker Engine.
- `ssh` — создание пользователя `devops`, установка открытого SSH-ключа, настройка sudo, SSH и UFW.
- `nginx` — установка и настройка Nginx в качестве обратного прокси для приложения.
- `app` — загрузка Docker-образа из GHCR, запуск контейнера и проверка его работоспособности.

### Docker-образ приложения

Используется проверенный образ из GitHub Container Registry:

`ghcr.io/aka-belka/devops-ci-app:49ceae7488c300099aa9d624be821f91ad5532c2`

В качестве тега применяется полный SHA коммита, что позволяет однозначно определить версию приложения.

Имя контейнера: `devops-ci-app`.

Внутренний порт приложения — `5000`. Порт хоста — `5000`; приложение доступно локально на VM через `127.0.0.1:5000`. Внешние HTTP-запросы принимаются Nginx на порту `80`.

Health endpoint приложения: `/health`. Успешный ответ содержит JSON `{"status":"ok"}` и HTTP-код `200`.

### Запуск конфигурации

Первоначальная настройка сервера выполняется командой:

```bash
ansible-playbook -i inventory/bootstrap.ini site.yml --ask-pass --ask-become-pass
```

Для последующих запусков используется SSH-ключ и production inventory:

```bash
ansible-playbook -i inventory/prod.ini site.yml
```

Повторный запуск проверяет соответствие сервера описанной конфигурации и при отсутствии изменений завершается с `changed=0`.

### Read-only аудит

Для проверки результата развёртывания без изменения конфигурации используется отдельный playbook `verify.yml`:

```bash
ansible-playbook -i inventory/prod.ini verify.yml
```

Аудит проверяет эффективные настройки SSH, состояние Docker-контейнера и ответ приложения на health endpoint. Успешный запуск завершается с `changed=0`.
