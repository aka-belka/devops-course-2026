## 1. Когда я выберу rebase, а когда merge? Почему?

Rebase лучше выбирать, когда необходима чистая, линейная история. Также с rebase лечге читать git log. Поэтому с rebase удобно работать в личной ветке.
Merge я выбираю для работы в публичной ветке, поскольку существующие коммиты не переписываются и сохраняется полная история.

## 2. Что произойдёт, если я сделаю rebase публичной ветки, с которой работают коллеги?

Rebase перезапишет историю, в результате чего у коллег останется старая версия. Когда коллеги попробуют сделать git pull, Git либо попытается слить две несовместимые истории и создаст множество конфликтов, либо просто откажется обновлять ветку. Все локальная работа будет потеряна.
